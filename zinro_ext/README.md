# zinro_ext(RM補助の Chrome 拡張)

zinro.net の村主(RM)が自分で使う運営補助。配役プリセット、追放 / 観戦のみ / 除外のリスト、荒らしの自動追放(試運転つき)、参戦者を観戦へ移す操作。

- AI 参加者ではない。ゲームには参加せず、チャットへの自動投稿もしない(このリポジトリのボットが zinro.net に接続しない方針とは別物で、人間の RM が使う運営補助)。
- 外部のサーバーとは通信しない。通信先は zinro.net だけ(同一オリジン)。manifest の権限は `storage` のみ。
- 提供が終わった旧拡張(人狼オンライン戦績解析機〈サプリの小道具〉)のうち、サーバーが要らない機能だけを作り直したもの。旧拡張のコードは使っていない。サイトの形(参加者API、チャット欄のDOM、KICK の URL、配役の組み合わせ)は、旧拡張が公開していた実装から読み取った事実を参考にした。戦績・顔ぶれ・称号・掲示板など、サーバーのデータが要る機能は入れていない。

> 続きを別の環境(手元のローカルなど)で進めるときは、[HANDOVER.md](HANDOVER.md)(実サイトで確かめる前提の一覧、確認用のスニペット、次のセッションに貼るプロンプト)を読む。

## 入れ方

1. Chrome の `chrome://extensions` を開き、右上の「デベロッパー モード」を入れる。
2. 「パッケージ化されていない拡張機能を読み込む」で、このフォルダ(`zinro_ext/`)を選ぶ。
3. zinro.net の村(`/m/player.php`)を開くと、右下に「RM補助」が出る。RM でなければ灰色で、自動の処理はしない。

## 最初は試運転で確かめる

初期状態は**試運転**(橙色の「RM補助 🧪」)。自動の追放・観戦移動はせず、「追放するところでした」と記録して通知するだけ。手動の操作(参加者表のボタン、配役、観戦に移動)は試運転でも実行される。

実サイトでチャット欄の読み取りが正しいか(発言者と本文の分け方)は、この拡張の開発環境では確かめられていない(下の「確かめていないこと」)。次の順で確かめてから、本番にする。

1. 身内の村で、「荒らし」タブの「最近の検知・処理」を見ながら、誰かに結合文字(マヨビーム)や長文を貼ってもらう。ログの名前が、実際の発言者と一致すること。
2. 「荒らし」タブの「判定テスト」に、過去の荒らしの発言を貼って、点数を見る。
3. 問題なければ、パネル上の「本番にする」。

## 機能

| タブ | 内容 |
|---|---|
| 配役 | 27種のプリセット(4A〜19D猫)をボタン1つで変更。押すとサイトの配役を変えて、ページを再読み込みする。選んだ配役は、観戦移動のあとに戻す先として覚える |
| リスト | 追放 / 観戦のみ / 除外。酉(完全一致、◆の有無は無視)と名前(部分一致、全角半角・大文字小文字は無視)。貼り付けでの一括取り込み、書き出し、メモ、検索、動作の変更。自動で登録したものには「自動」の印が付く |
| 荒らし | 検知ルールごとの有効 / しきい値 / 点、追放ライン、試運転、判定テスト、検知の記録、追放ログ(保存。ここからリストへ登録できる) |
| 観戦 | 参戦者を観戦へ移す。ゲーム開始前だけ。約20秒かかる |
| 履歴 | このタブを開いてから入室した人。ここからリストへ登録できる |

参加者表(サイト本来の表)の右端に、RM だけに「追放」「観戦」のボタンが付く(「観戦」は開始前の参戦者だけ)。「追放」は、追放と同時に酉(公開されているもの)をリストへ登録するかを選べる。

### リスト

- **追放**: 入室したら自動で追放する。
- **観戦のみ**: 観戦にいるのはよいが、参戦にはしたくない人。参戦していたら、ゲーム開始前に観戦へ移す(配役を選んでいることが前提。下の「観戦に移す仕組み」)。
- **除外**: 荒らし判定とリストの自動処理の対象にしない(手動の操作は別)。
- 同じ人が複数に当たるときの優先は、除外 > 追放 > 観戦のみ。
- 酉が公開されていない人は、名前でしか登録できない。名前は部分一致なので、短い名前は他の人にも当たる。本番のときは、今いる人に当たる追加の前に確認が出る。
- 取り込みの書式(1行に1件。`# メモ` は任意):

  ```
  ◆abcDEF1234 # 何度も来る
  ミドリ (◆Zx9/Qw+k1LmN)      ← サイトの表示のまま貼ってよい。酉を拾い、名前はメモになる
  name:連投の人               ← 種別を指定(trip: / name:)
  [観戦のみ]                  ← 以降の動作を切り替える([追放] [観戦のみ] [除外])
  ◆Pq7Rs8Tu9V # 参戦不可
  ```

## 荒らしの検知(点数制)

発言1つを調べて、当たったルールの点を、その人に積む。合計が**追放ライン(既定2点)**に届いたら追放し、1点だけなら警告の通知にとどめる。点は30分で消える(変更できる)。リストの「除外」の人、RM自身、システム(鯖)は対象外。

| ルール | 既定のしきい値 | 当たる条件 | 点 |
|---|---|---|---|
| マヨビーム | 12字 | 4つ以上積み重なった結合記号と、不可視の制御文字の合計 | 1 |
| ジャワ文字 | 8字 | ジャワ文字(U+A980〜A9DF)の数 | 1 |
| ログの貼り付け | 4個 | 「参加者名: 」「鯖: 」の形が4個以上で、3人以上、または鯖入り | 1 |
| 定義文・AI文章の貼り付け | 200字・構造3 | 長文で、箇条書き・定義文(「〜とは、〜のこと」)・「項目: 説明」・見出し語のうち3つ以上が揃い、ゲームの話題ではない(話題内なら4つ) | 1 |
| 入室直後の長文 | 120字・180秒・5字/秒 | 入室を見てから180秒以内に、5字/秒を超える速さで120字以上 | 1 |
| 同一内容の連投 | 5回・15秒 | 同じ発言(3字以上)が15秒以内に5回 | 2 |
| 上限ぴったり(加点) | 上限の10字以内 | 上の貼り付け3つのどれかが当たった発言が、1発言の上限字数(既定255字)に届いている | 1 |

- マヨビームとジャワ文字は、同じ発言の中では合わせて1点まで。つまり「2回以上投稿したら追放」。1文字や数文字では当たらない。
- **同一文字の連続(「あああ」「wwww」)や、短い語句の繰り返し(「うんうんうん」)は検知しない**。人の発言でも出るため。
- 絵文字(異体字選択子・ZWJ・キーキャップ)、日本語の濁点の結合記号、タイ語・アラビア語などの母音記号は、結合文字として数えない。
- 「上限ぴったり」は、貼り付けの根拠が別にあるときだけ加点する。長いだけの発言は点にならない。実例の貼り付け2件は、どちらもサイトの上限で文の途中で切れていた。人が打った文章は、上限ぴったりには届きにくい。
- 実際に出た荒らしの2つの形は、どちらも1発言で2点(追放ライン)に届く:
  - 辞書のような解説文の貼り付け(定義文・見出し・「項目: 説明」・箇条書き。253字で途切れていた)→ 定義文・AI文章の貼り付け + 上限ぴったり
  - 部屋のチャットログの貼り付け(「名前: 発言」が13個、「鯖:」入り。255字で途切れていた)→ ログの貼り付け + 上限ぴったり

  ログの貼り付けは、他人の発言を偽装できる。単独(上限に届かない短い貼り付け)では1点で、警告にとどまる。見つけたらすぐ追放したいときは、「ログの貼り付け」の点を2にする(人が数行を引用することはあるので、既定は1点)。
- しきい値と点は、「荒らし」タブで変えられる。「判定テスト」に文章を貼ると、どのルールに何点当たるかが見え、しきい値を変えるとその場で更新される。

## 観戦に移す仕組み

旧拡張が使っていた手順と同じで、ワードウルフ機能の「お題役」を使う。

1. ワードウルフを ON → 2. お題役に対象を指定 → 3. ワードウルフを OFF → 4. 配役を元に戻す

途中で失敗したときは、ワードウルフを切って配役を戻す後始末を試みる。**配役を戻すには、このツールで選んだ配役が要る**ので、未選択のままでは、自動では移さない(手動のときは、警告つきの確認が出る)。サイトの画面で配役を手で変えたあとは、「配役」タブでもう一度選び直す。

## 安全装置

- 試運転(初期状態)。
- 同じ人への自動の追放は3回まで、観戦移動は2回まで。効かないときに、再読み込みを繰り返さない。
- 読み込み直後の数秒は、チャットの履歴が遅れて描画されても判定しない。点が付いた発言は、リロードをまたいで一度しか数えない。
- RM でなければ、何も自動では行わない。
- 追放・観戦移動は1つずつ順に行い、サイトへの通信は間隔をあける(参加者API 1.2秒、player.php 2秒)。
- 他人の名前・発言は、HTML として解釈させずに表示する。パネルは Shadow DOM で、サイトの CSS やキー操作と混ざらない。

## 保存するもの

すべてこのブラウザの中だけ。どこにも送信しない。

- `chrome.storage.local`: 設定、リスト、選んだ配役、追放ログ(最新100件)。
- `sessionStorage`(タブを閉じると消える): 点、入室履歴、検知の記録。

## 入れなかったもの

- 戦績・顔ぶれ・称号・因縁・MVP・村一覧のバッジ・掲示板・お知らせ・割れ酉リスト・トリップ本人名照合: 旧拡張の作者のサーバーのデータが要るため。
- 旧拡張の「情報」パネルのうち、使用時間(参加者の更新のたびに保存領域へ書き込んでいた)、フレンド(他村の確認が、村一覧の RM の酉しか見ないため不正確)、サーバー状態。入室履歴だけを「履歴」タブに残して、リストへの登録と結びつけた。
- 点呼、人数の警告、接続切れの警告、他村パネル: 要望になかったため。必要なら足す。
- 荒らしの検知のうち、同一文字の連続、短い語句の繰り返し、「文字の重なりで測る類似連投」: 人の発言でも出るため(旧拡張のコードを読むと、「うんうんうんうんうん」でも追放になる)。

## テスト

```
node --test zinro_ext/tests/*.test.js                  # 単体テスト。python -m unittest からも呼ばれる
node --test --test-concurrency=1 zinro_ext/tests/e2e/zinro_e2e.test.js   # 実際の拡張を Chromium で動かす(要 Playwright。1分半ほど)
```

- 単体テストは、判定ルール・リスト・配役・サイトの読み取り・新しい発言の取り出し・manifest と静的な前提(外部へ通信しない、HTML として入れない)。テストの入力は、実在の発言を使わない合成のデータ(`tests/fixtures.js`)。
- 発言例(`knowledge/examples.jsonl` の444件、匿名化済み)に、既定の設定では1件も当たらない。しきい値をわざと緩めると当たるので、このテストは空ではない。
- E2E は、実際の拡張を Chromium に読み込み、`https://zinro.net/` へのすべての通信を模擬サイト(`tests/e2e/mock_site.js`)に差し替えて動かす。zinro.net 以外への通信がないことも、毎回検査する。

## 確かめたこと / 確かめていないこと

確かめたこと:

- 判定ロジックと、画面の操作(追放・観戦ボタン、配役、リスト、荒らし判定、試運転、観戦移動の4手順と配役の復元、リロードをまたぐ点の保持、追放が効かないときの3回での停止、RM でないときの無動作、入力途中の内容の保持)を、上のテストで。
- 依頼者が貼った実際の荒らしの2件(生ログなのでリポジトリには入れていない)を判定にかけ、どちらも1発言で2点に届くこと。
- 模擬サイトの形のとおりに、拡張が動くこと。

確かめていないこと:

- **実サイト(zinro.net)での動作**。開発環境から zinro.net に届かない。模擬サイトは、旧拡張の実装から読み取った形の再現で、サイトが実際と違えば動かない。特に、チャット欄の読み取り(発言者と本文の分け方)が違うと、判定が当たらない(安全側)か、別の人を指す(危険側)。だから試運転から始める。
- 観戦移動の4手順が実サイトで効くこと(旧拡張と同じ手順を使っている)。
- 1発言の上限字数。貼り付けた2件が253字・255字で途切れていたことから255字と推定した。設定で変えられる。
- 荒らしの見落とし。確かめたのは、実例の2件と、それを真似た合成の例だけ。名前を混ぜる、改行を挟むなど、検知を避ける工夫は想定していない。
- サイトの規約で、RM による自動の追放や観戦移動が許されるか(旧拡張は公開されていた)。

## 限界

- 別名・酉なしで何度も来る荒らしには、リストが効かない。荒らし判定が頼り。
- 参加者表のボタンと、チャット欄の読み取りは、サイトの表と DOM の作りに依存する。サイトが変わったら、`src/lib/zinro.js` を直す。
- 同じ村を複数のタブで RM として開くと、どちらも自動で動く(二重の追放要求になる)。
