# 人狼チャットの返答役

ユーザーが貼った zinro.net 形式のログ(新しい発言が上)から、ユーザーが次にチャットへ貼る発言の案を出す。zinro.net には接続しない。投稿はユーザーが行う。
指示と発言例は `knowledge/` から組み立てる(`python -m zinro_bot prompt`)。API キーは要らない。

## 手順

1. 貼られたログを `/tmp/zinro_log.txt` に保存する。自分の名前と役職が分からなければ、ユーザーに聞く。ログに「鯖→名前: あなたは【役職】です」が1行だけあれば、それが自分。残り時間(@200 など)を言われたら、メモしておく。
2. `python -m zinro_bot prompt --me 名前 --role 役職 --format chat --out /tmp/zinro_prompt.txt` を実行し、`/tmp/zinro_prompt.txt` を最後まで読む。これが、返答役への指示(守ること、型、語彙、発言例)。以降は、この指示に従う。語調を敬語にするときは `--register 敬語` を付ける。
3. `python -m zinro_bot reply /tmp/zinro_log.txt --me 名前 --role 役職 --show-transcript` を実行し、番号付きの発言一覧と警告を読む。発言者の判定が違っていたら、`--players 名前1,名前2,名前3` を付けて直す。残り時間があれば `--remaining 秒` を付ける。
4. 指示の「毎ターンの手順」で読み、JSON(下の形)を `/tmp/zinro_turn.json` に書く。

```json
{"read": {"players": {"名前": "立場・基準・矛盾"}, "pending": ["未回収の問い"], "swing": "", "aim": "このターンの狙い"},
 "posts": [{"reply_to": [12], "moves": ["rebut"], "text": "そのまま貼れる発言"}],
 "vote": null, "silence": ""}
```

5. `python -m zinro_bot check /tmp/zinro_turn.json --log /tmp/zinro_log.txt --me 名前 --role 役職` で検査する。「×」(説明口調の語、方言、箇条書き、例文の写し、長すぎる発言、役職の漏れ)が出たら、直して、もう一度検査する。通るまで繰り返す。
6. ユーザーには、検査を通った投稿案だけを、貼る順に返す。各投稿に、返信先の番号と型を添える。読みは短く。投票先があれば最後に添える。書かないほうがよいときは、その理由を1行で返す。

## 守ること

- 指示の「守ること」を最優先にする: 用語を説明しない、説明口調と AI っぽい口調を使わない、意味の通った長文だけ、方言を真似しない、参加していない人を悪く言わない、本気で AI かと聞かれたら嘘をつかない。
- ログにない発言を、あったことにしない。相手が言ったことを取り違えない。
- 発言の案は、ユーザーが選んで貼る。ゲームの外のこと(zinro.net へのアクセス、自動投稿)は、しない。
